Webアプリの基本概念

HTML・CSS・JavaScript・DOM・イベント・非同期処理・PWA・Service Worker・アクセシビリティまで、実際のソースに登場した概念を一枚の教材として整理。

1. まず全体像

HTML ── 画面の構造を作る │ ├─ CSS ── 見た目・配置・表示状態 │ └─ JavaScript ── 動作・判断・操作 │ ├─ DOM ── HTMLをJSから操作 ├─ Event ── タップや状態変化を待つ ├─ Promise ── 後で結果が返る処理 └─ Web API ── ブラウザの機能を利用 │ └─ Service Worker → PWA

このアプリは「HTMLだけのページ」ではなく、複数のWeb技術を組み合わせたWebアプリになっています。

2. HTMLの基本

HTML
要素（element）

div、img、button、h1、pなど。画面に存在する部品。

HTML
属性（attribute）

id、src、href、altなど。要素に追加情報を与える。

HTML
head / body

headはページの設定、bodyは実際の画面内容。

HTML
meta

文字コード、画面幅、テーマカラーなど「ページについての情報」を指定。

<img
  id="noteImage"
  src="keyboard-chart.png"
  alt="初黄から十一までの25鍵の鍵盤図"
  draggable="false"
>

imgが要素、id / src / alt / draggableが属性です。

3. HTML・CSS・JavaScriptの分業

技術役割このアプリなら
HTML何が存在するか鍵盤画像、＋−ボタン、情報ダイアログ
CSSどう見えるか位置、サイズ、色、非表示状態
JavaScriptどう動くかタップ処理、音、キー変更、更新通知
HTML = 骨格　／　CSS = 見た目　／　JavaScript = 動作

4. id と DOM

idはHTML部品につける固有名です。

<div id="updateNotice">更新があります</div>

JavaScriptから、その名前を使って部品を取得できます。

const updateNotice =
  document.getElementById("updateNotice");

updateNotice.style.display = "block";
HTMLの要素 ↓ idで探す document.getElementById() ↓ JavaScriptから取得 ↓ 内容・見た目・状態などを操作

DOMとは、HTMLをJavaScriptから「操作できるもの」として扱うための仕組みです。

5. JavaScriptの基本概念

JavaScript
変数 / const

値やオブジェクトに名前をつけて扱う。

JavaScript
関数 function

一連の処理を部品化し、名前をつける。

JavaScript
if

「もし○○なら」を表す条件分岐。

JavaScript
return

その関数の処理をそこで終了する。

JavaScript
===

左右が同じか厳密に比較する。=は代入。

JavaScript
&&

AND。「AかつB」の両方が成立する条件。

6. オブジェクト・プロパティ・メソッド

newWorker.state

navigator.serviceWorker.register("./sw.js")
形意味
newWorker.stateプロパティ。「newWorkerが持つstateという情報」
serviceWorker.register()メソッド。「serviceWorkerが持つregisterという処理」
覚え方： ○○.△△なら「○○が持っている△△」。括弧 () が付けば、たいてい何らかの処理を実行しています。

7. 引数と戻り値

"./sw.js" ↓ 引数（処理に渡す材料） register("./sw.js") ↓ 処理 結果 ↓ 戻り値

関数やメソッドには、材料を渡す「引数」と、処理後に返ってくる「戻り値」があります。

8. イベントとコールバック

registration.addEventListener(
  "updatefound",
  function() {
    // 更新が見つかったときの処理
  }
);
「updatefound」が起きるのを待つ ↓ イベント発生 ↓ 預けておいた関数を実行 ↑ コールバック関数

イベント駆動とは、「タップされた」「更新が見つかった」「状態が変わった」などの出来事をきっかけに処理する考え方です。

9. Promise と非同期処理

navigator.serviceWorker
  .register("./sw.js")
  .then(registration => {
    // 成功
  })
  .catch(error => {
    // 失敗
  });
Service Workerを登録 ↓ 処理中…… ↓ ┌─────┴─────┐ ↓ ↓ 成功 失敗 ↓ ↓ .then() .catch() ↓ ↓ registration error

Promiseは、「今すぐ結果は渡せないけれど、終わったら結果を知らせる」という仕組みです。通信やService Workerなど、時間のかかる可能性がある処理で重要になります。

10. アロー関数

.then(registration => {
  console.log("成功");
})

=>を使った書き方をアロー関数と呼びます。上の例では、処理成功時に渡された結果をregistrationという名前で受け取っています。

// 従来型で概念的に近い書き方
function(registration) {
  console.log("成功");
}

11. Web API と navigator

JavaScriptだけでブラウザの全機能を自作するわけではありません。ブラウザが提供する機能をWeb APIとして利用します。

document

HTML（DOM）を操作する入口。

navigator

ブラウザや端末に関係する機能への入口。

console

開発者ツールへログやエラーを出力。

serviceWorker

Service Workerを登録・管理するためのAPI。

12. PWA と Service Worker

PWA

PWA（Progressive Web App）は、Webページをインストール可能にしたり、オフラインでも利用できるようにしたりして、アプリに近い使い方を可能にする仕組みです。

manifest.json ── アプリ名・アイコン等の設定 ＋ Service Worker ── キャッシュ・オフライン・更新 ↓ PWA

Service Workerのライフサイクル

新版を発見 ↓ updatefound installing ↓ installed ↓ waiting ↓ 適切なタイミングで新版へ交代

ライフサイクルとは、あるものが時間とともに複数の「状態」を移っていく考え方です。

13. アクセシビリティとスクリーンリーダー

Accessibility

スクリーンリーダーは、画面の情報やHTMLの意味を利用して、主に音声で内容や操作対象を伝える支援ソフトウェアです。

<button
  aria-label="このアプリについて"
>
  ⓘ
</button>

見た目では「ⓘ」でも、aria-labelによって「このアプリについて」という意味を支援技術に伝えられます。

仕組み役割
alt画像の代替テキスト
aria-label要素に分かりやすい名前を与える
role="dialog"その領域がダイアログであることを伝える
aria-modal="true"モーダルダイアログであることを伝える
aria-labelledby別の要素を「名前・見出し」として関連付ける
aria-hidden支援技術から隠す状態を表す

14. ARIAとは？

ARIA（読み：アリア）

Accessible Rich Internet Applications の略です。

Accessible

利用しやすい、アクセス可能な

Rich Internet Applications

高機能なWebアプリケーション

HTMLだけでは支援技術に伝わりにくい意味や状態を補足するための仕組みです。

ポイント：「aria」という属性が一個あるのではなく、aria-label、aria-hidden、aria-modalなど、aria-○○という属性群をARIAと呼びます。

15. 最後に：全部を一本につなぐ

HTMLで部品を作る ↓ CSSで見た目を作る ↓ idを手がかりにDOMから取得 ↓ JavaScriptで操作 ↓ イベントを待つ ↓ 関数・コールバックを実行 ↓ 必要ならWeb APIを使う ↓ 時間がかかる処理はPromiseで扱う ↓ Service Workerなどを利用 ↓ PWAとしてアプリらしく動く そして横断的に ↓ アクセシビリティ / ARIAで 人や支援技術に「意味」を伝える
